# 项目笔记 / 项目结论

## 一、项目定位
本项目基于电商零售订单数据，完成 MySQL 离线数仓建模、Hive 迁移和 DolphinScheduler 调度编排三个阶段。

## 二、项目核心分析主线
1. 客户结构分析：通过 Top10、Top50 客户销售贡献占比判断平台收入集中度。
2. 客户价值分层：基于客户累计消费金额划分 High Value、Medium Value、Low Value。
3. 高价值客户行为分析：分析偏好商品、下单频次、国家分布和销售贡献。
4. 国家市场质量分析：区分销售规模大和客户质量高的国家市场。
5. 商品结构分析：观察热销商品和高价值客户偏好商品。

## 三、工程化亮点
1. MySQL 阶段完成 ODS、DWD、DWS、ADS 四层建模。
2. Hive 阶段使用 dt 分区、ORC 存储、bizdate 参数和 INSERT OVERWRITE PARTITION。
3. DolphinScheduler 阶段将 Hive 链路拆分为 10 个 Shell 任务节点，形成 ODS、DWD、DWS、ADS、数据质量校验的 DAG 依赖。
4. 补充 etl_task_log_v2 和 dq_check_result 表设计，为后续任务状态追踪和质量校验结果落表提供扩展基础。

## 四、面试时可主讲的核心结论
1. 项目不是单纯 SQL 查询，而是从 MySQL 数仓建模扩展到 Hive 迁移，再扩展到 DolphinScheduler 调度编排。
2. 指标主线围绕高价值客户展开，形成客户分层、客户偏好、客户活跃度、国家分布和销售贡献的闭环分析。
3. Hive 迁移重点体现分区设计、列式存储、参数化重跑和幂等写入。
4. DolphinScheduler 接入重点体现任务拆分、依赖编排、业务日期参数、运行验收和失败后可重跑。

## 五、后续可优化方向
1. 完善 DolphinScheduler 元数据库持久化。
2. 使用 SSH 免密或密钥方式执行远程任务。
3. 将质量校验结果落入 dq_check_result 表。
4. 将每个任务的 START、SUCCESS、FAILED 状态写入 etl_task_log_v2 表。
5. 增加失败告警、重试策略和 Superset 指标看板。
